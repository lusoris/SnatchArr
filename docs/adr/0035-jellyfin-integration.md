# ADR-0035: Complete SnatchArr integration inside Jellyfin without an external identity provider

- Status: Accepted (operator answers recorded 2026-10-26, ledger ids `snatcharr-oq-0035-1` to `snatcharr-oq-0035-4`)
- Date: 2026-10-26
- Related: [ADR-0012](0012-queue-management-replaces-cleanuparr-link.md), [ADR-0018](0018-product-front-door.md), [ADR-0021](0021-llm-access-module.md), [ADR-0023](0023-sso-viewer-role.md), [ADR-0024](0024-watch-aware-modes.md), [ADR-0025](0025-module-switches.md), [ADR-0026](0026-accounts-and-roles.md), [ADR-0027](0027-adult-module.md), [ADR-0028](0028-jellyfin-plugin.md), [ADR-0029](0029-task-flow-ui.md), [ADR-0031](0031-creator-content-fansdb.md), [ADR-0032](0032-stash-own-or-integrate.md), [ADR-0033](0033-adult-identity-and-model.md)

## Context

**SnatchArr** (`/ˈsnætʃ.ɑːr/`, from English "snatch" — to grab a media release — plus the `-arr` suffix of the **Servarr** `/ˈsɜːr.vɑːr/` automation family) serves as the operational front door of the media stack ([ADR-0018](0018-product-front-door.md)). **Jellyfin** (`/ˈdʒɛl.i.fɪn/`, the free-software media server forked from Emby in December 2018, blending "jellyfish" and "fin") is the household media server where users browse libraries, watch shows, and manage playback.

The fleet's media products bring all their functions into Jellyfin itself so that any adopter can operate the entire stack from inside Jellyfin using only their Jellyfin account:

1. **Any-adopter constraint (no cluster, reverse proxy, or identity provider assumed)**: A typical adopter runs Jellyfin, SnatchArr, and one or more `*arr` applications — **Sonarr** (`/ˈsoʊ.nɑːr/`, television series, from "sonar" + `-arr`), **Radarr** (`/ˈreɪ.dɑːr/`, films, from "radar" + `-arr`), **Lidarr** (`/ˈlaɪ.dɑːr/`, music, from "lidar" + `-arr`), **Readarr** (`/ˈriː.dɑːr/`, books, from "reader" + `-arr`), and **Whisparr** (`/ˈwɪs.pɑːr/`, adult video scenes, from "whisper" + `-arr`) — plus **Prowlarr** (`/ˈpraʊ.lɑːr/`, indexer manager, from "prowl" + `-arr`) on a single host or home NAS without Kubernetes, an ingress reverse proxy, or **Authentik** (`/ɔːˈθɛn.tɪk/`, open-source identity provider, from "authentic") / OpenID Connect (OIDC). Third-party media servers outside the fleet's products (such as Audiobookshelf or RomM) are out of scope.
2. **What [ADR-0028](0028-jellyfin-plugin.md) already decides**: ADR-0028 establishes the companion C# plugin repository (`lusoris/jellyfin-plugin-snatcharr`, licensed under `GPL-3.0-or-later`), adult scene metadata and `PhotoAlbum` gallery delivery, request routing boundaries with **Seerr** (`/ˈsiː.ər/`, formerly Jellyseerr `/ˈdʒɛl.i.siː.ər/` and Overseerr `/ˈoʊ.vər.siː.ər/`, media request manager from "overseer" / "seer"), and user token verification against Jellyfin `GET /Users/Me` (`snatcharr-jellyfin-plugin-user-auth-method`). However, ADR-0028 scoped the plugin to adult metadata, image-set galleries, status badges, and request modals, leaving SnatchArr's remaining 105 OpenAPI operations (`api/openapi/openapi.yaml`) and 18 single-page application (SPA) routes (`web/src/routes/`) exclusively in the standalone web UI.
3. **What [ADR-0026](0026-accounts-and-roles.md) already decides and where it assumes an external IdP**: ADR-0026 defines the three roles (`viewer`, `requester`, `admin`), Jellyfin credential sign-in (`POST /api/v1/auth/jellyfin`), Quick Connect (`POST /api/v1/auth/jellyfin/quickconnect/*`), and the `user_identities(provider, subject) -> user_id` linking table (`api/internal/auth/identity.go`). Its implementation in `api/internal/httpapi/handlers_jellyfin.go` and `api/internal/auth/service.go` still assumes that a local password administrator (`POST /api/v1/auth/setup`) or OIDC/proxy SSO account is provisioned first, returning `409 Conflict` when a Jellyfin administrator signs in before `/setup` (`handlers_jellyfin.go:88-96`) or when an already-provisioned Jellyfin user later links an external identity (`identity.go:55-68`).

## Decision

### 1. Integration shape: one UI served inside Jellyfin via the plugin BFF proxy

Rather than building and maintaining a second frontend in C# or vanilla JavaScript for 105+ operations (which would violate HISS-19's single-implementation invariant), `lusoris/jellyfin-plugin-snatcharr` acts as a same-origin Backend-for-Frontend (BFF) proxy and host for SnatchArr's built SvelteKit SPA (`web/`, built on **sveltesentio** `/ˌsvɛltˈsɛn.ti.oʊ/`, the Lusoris Svelte 5 component library from "Svelte" + Latin *sentio*, "I perceive"):

```mermaid
sequenceDiagram
    autonumber
    participant Browser as Jellyfin Web / Desktop Client
    participant Plugin as Jellyfin Server + SnatchArr Plugin (/SnatchArr/*)
    participant API as SnatchArr API (api/)
    participant JFAuth as Jellyfin /Users/Me

    Browser->>Plugin: GET /SnatchArr/app (or item detail action) + Authorization: MediaBrowser Token=<jf-token>
    Plugin->>Plugin: CustomAuthenticationHandler validates <jf-token>, checks !User.GetIsApiKey()
    Plugin->>API: POST /api/v1/auth/jellyfin { "access_token": "<jf-token>" }
    API->>JFAuth: GET /Users/Me (X-Emby-Token: <jf-token>) via goenvoy/jellyfin
    JFAuth-->>API: 200 OK (Id, Name, Policy.IsAdministrator, Policy.IsDisabled, ParentalPolicy)
    API-->>Plugin: 200 OK + Set-Cookie: snatcharr_session (Path=/SnatchArr/api; HttpOnly; SameSite=Lax)
    Plugin-->>Browser: Same-origin session established; proxies /SnatchArr/api/v1/* and SSE /SnatchArr/api/v1/events
```

1. **Same-origin plugin proxy (`/SnatchArr/app/{**path}` and `/SnatchArr/api/v1/{**path}`)**:
   - The C# plugin registers `SnatchArrProxyController` (`[ApiController]`, `[Route("SnatchArr")]`) inside Jellyfin Server.
   - Requests to `/SnatchArr/app/{**path}` stream the static SPA assets embedded in the paired SnatchArr API instance (`api/internal/web`), so upgrading SnatchArr immediately updates all 18+ UI routes inside Jellyfin without requiring a lockstep C# plugin rebuild.
   - Requests to `/SnatchArr/api/v1/{**path}` (including Server-Sent Events on `GET /SnatchArr/api/v1/events` streamed with `HttpCompletionOption.ResponseHeadersRead` and `X-Accel-Buffering: no`) are proxied over the local host/container network to `SnatchArrUrl`. Adopters never have to expose SnatchArr's port, configure TLS certificates for a second hostname, or set Cross-Origin Resource Sharing (CORS) headers.
2. **Embedded shell mode in `web/`**:
   - When `web/` runs under `/SnatchArr/app` (or detects the Jellyfin host bridge), it activates embedded layout mode: it hides standalone sign-in/setup chrome, reads the caller's Jellyfin `accessToken()` from `window.ApiClient` (or receives the plugin-exchanged session cookie), synchronizes locale (`en`/`de`) and dark/light `oklch` theme variables with Jellyfin, and filters its navigation bar by the user's resolved role (`viewer`, `requester`, `admin`) and active modules (`listModules`).
3. **Web injection through an optional JavaScript Injector snippet (refining [ADR-0028](0028-jellyfin-plugin.md) OQ-3; ledger `snatcharr-jellyfin-plugin-web-injection-method`)**:
   - The plugin does not rewrite `/web/index.html` or `/web/config.json`. It ships `SnatchArr/client.js` plus an optional snippet for `n00bcodr/Jellyfin-JavaScript-Injector`; the snippet loads `client.js`, which adds the **SnatchArr** navigation entry, mounts the in-app `#/snatcharr` route (`OQ-0035-1`), adds item-detail actions on `#/details`, adds a request or wish button to every poster and item card (`OQ-0036-6`, ledger `snatcharr-oq-0036-6`), and adds optional status rails on `#/home`.
   - Every server-side feature works with the injector absent: `/SnatchArr/app`, Dashboard -> Plugins -> SnatchArr (`/web/ConfigurationPage?name=SnatchArr`), the request and vote API, background playback events and the plugin proxy. The plugin documents the injector as optional and writes a log line at start when it is missing, so a missing button is never a silent fallback.
   - Rationale (ledger, derived 2026-10-24): rewriting the jellyfin-web bundle or its served files breaks on Jellyfin Web bundle changes; the injector snippet keeps the plugin out of jellyfin-web internals.

### 2. Plugin-to-SnatchArr authentication and delegation without an IdP

Two mechanisms for authenticating plugin requests on a Jellyfin user's behalf without an external IdP were weighed:

| Criterion | Option A: Shared plugin API key + forwarded `X-Jellyfin-User-Id` header | Option B: Jellyfin user access-token exchange validated via `GET /Users/Me` (Chosen) |
| :--- | :--- | :--- |
| **Mechanism** | Plugin authenticates caller via `[Authorize]`, extracts `User.GetUserId()`, and sends `Authorization: Bearer <plugin-key>` + `X-Jellyfin-User-Id: <guid>` to SnatchArr, which maps `(provider='jellyfin', subject=<guid>)`. | Plugin (or embedded SPA via plugin proxy) forwards the caller's verified Jellyfin session token (`User.GetToken()`) to `POST /api/v1/auth/jellyfin`; SnatchArr validates it against Jellyfin `GET /Users/Me` via **goenvoy** (`/ɡoʊˈɛn.vɔɪ/`, Lusoris Go API client library, from "Go" + "envoy") and mints a `snatcharr_session`. |
| **Compromise blast radius** | **Critical (confused deputy)**: Any leak of the single plugin API key (`Jellyfin.Plugin.SnatchArr.xml`) or SSRF on the local network allows arbitrary impersonation of every household user and `admin` by forging `X-Jellyfin-User-Id`. | **Contained**: No static key can impersonate a user. Every user/admin session requires a live Jellyfin user token verified against `GET /Users/Me` and revalidated every 5 minutes by `jellyfin.Revalidator` (`api/internal/jellyfin/revalidator.go:34-103`). |
| **Adult parental policy fidelity** | **Low**: SnatchArr must either trust unverified header claims for parental flags or query Jellyfin anyway. | **High**: `GET /Users/Me` returns the authoritative `UserDto.Policy` (`IsAdministrator`, `IsDisabled`, `MaxParentalRating`, `BlockUnratedItems`, `BlockedTags`, `EnableAllFolders`, `EnabledFolders`) directly from Jellyfin. |
| **Codebase reuse (HISS-19)** | **Poor**: Duplicates `proxy_auth` (`api/internal/httpapi/handlers_auth.go`) with a second trusted-header path. | **Exact**: Reuses `jellyfin.Authenticator.ByToken` (`api/internal/jellyfin/authenticator.go:63-91`), `startJellyfinSession` (`api/internal/httpapi/handlers_jellyfin.go:84-114`), and `jellyfin.Revalidator`. |

**Decision**: Adopt **Option B** (refining and confirming [ADR-0028](0028-jellyfin-plugin.md) OQ-4):

1. **Interactive user and admin calls**:
   - Every user-initiated request reaching `SnatchArrProxyController` requires `[Authorize]` on Jellyfin and explicitly rejects API-key callers (`if (User.GetIsApiKey()) return Forbid();`, guarding against `CustomAuthenticationHandler.cs:50-54`).
   - When the browser has no active `snatcharr_session` cookie (or its `sso_subject` does not match `User.GetUserId()`), the plugin exchanges `User.GetToken()` against SnatchArr's `POST /api/v1/auth/jellyfin` (`jellyfinLogin`), which verifies the token via `GET /Users/Me` (`Jellyfin.Api/Controllers/UserController.cs:581`) and returns an `HttpOnly` session cookie plus CSRF token (`getSession`).
   - Subsequent requests through `/SnatchArr/api/v1/*` carry that session cookie; `jellyfin.Revalidator` (`api/internal/jellyfin/revalidator.go`) re-verifies the user's active status, administrator bit, and parental policy against Jellyfin every 5 minutes (`revalidationInterval = 5 * time.Minute`).
2. **Background server-to-server calls**:
   - A scoped SnatchArr API key (`ApiKeyScope` `core:write`, `requests:read`) stored in `PluginConfiguration` is used **exclusively** for non-user background events (such as `ISessionManager.PlaybackStopped` watch-aware notifications and plugin health probes). SnatchArr ignores any `X-Jellyfin-User-Id` header on API-key requests.
3. **Threat model**:
   - *Forged or expired Jellyfin token*: Rejected at both layers — Jellyfin's `CustomAuthenticationHandler` returns `401 Unauthorized` before the plugin controller executes, and SnatchArr's `Authenticator.ByToken` returns `domain.ErrUnauthorized` (`401 application/problem+json`) if `GET /Users/Me` fails or `Policy.IsDisabled == true`.
   - *Privilege escalation (`viewer`/`requester` -> `admin`)*: Role assignment is computed solely inside SnatchArr from the `Policy.IsAdministrator` boolean returned by Jellyfin's `GET /Users/Me` (`domain.RoleForJellyfinMember` in `api/internal/httpapi/handlers_jellyfin.go:85`), never from client-supplied parameters.
   - *Adult content disclosure to restricted accounts*: Adult routes check both the `adult` module switch ([ADR-0025](0025-module-switches.md)) and the Jellyfin user's parental policy cached from `GET /Users/Me` ([ADR-0027](0027-adult-module.md)); unauthorized requests receive an indistinguishable RFC 9457 `404 Not Found` (`application/problem+json`).

### 3. Account paths

Re-checking [ADR-0026](0026-accounts-and-roles.md) (`api/internal/auth/identity.go`, `api/internal/auth/service.go`, `api/internal/httpapi/handlers_jellyfin.go`, `api/internal/httpapi/security.go`) shows three places where the current implementation assumes OIDC, reverse-proxy SSO, or a pre-existing local password administrator alongside Jellyfin:

1. **First-admin bootstrap barrier (`handlers_jellyfin.go:88-96`, `service.go:315-324`)**: Currently, when a Jellyfin administrator signs in via `POST /api/v1/auth/jellyfin`, `startJellyfinSession` calls `h.auth.FirstAdmin(ctx)`, which fails with `409 Conflict` (`ErrSetupRequired: initial admin setup has not been completed`) if `CountUsers == 0`. Non-admin Jellyfin users are similarly blocked until `SetupComplete` is true.
2. **Self-owned identity `409 Conflict` (`identity.go:55-68` `checkExternalIDOwnership`)**: When a user signs in with Jellyfin first, `ProvisionJellyfinUser` creates a `users` row with `external_id = "jellyfin:<uuid>"`. If the operator later enables OIDC or proxy SSO and that user calls `POST /api/v1/auth/identities/jellyfin` to link their Jellyfin identity, `checkExternalIDOwnership` sees `extUser.ID != userID` and rejects the link with `409 Conflict` (`identity belongs to another account`).
3. **Session `sso_role` override (`security.go:85-88`)**: `LoadSession` replaces `u.Role` with `ssoRole` when `sso_role` is non-empty on the session row, assuming the active SSO login source always dictates the role.

To guarantee that no external identity provider is ever assumed while preserving optional multi-IdP support for advanced deployments, SnatchArr defines five explicit account paths:

| Account path | Config / operations | Status & default | Role in architecture |
| :--- | :--- | :--- | :--- |
| **1. Jellyfin account** | `snatcharr.jellyfin.enabled` (`POST /auth/jellyfin`, `POST /auth/jellyfin/quickconnect/*`) | **Stays — primary default for Jellyfin adopters** (auto-enabled on plugin pairing) | Primary authentication and role source (`admin` from `Policy.IsAdministrator`, `requester`/`viewer` from `default_role` and parental policy) inside Jellyfin and on standalone `/login`. |
| **2. Local admin fallback** | `POST /auth/setup`, `POST /auth/login`, `POST /auth/password` | **Stays — break-glass & non-Jellyfin fallback** | Break-glass administrator login when Jellyfin is unreachable, and initial bootstrap for standalone deployments without Jellyfin. Never used for non-admin household accounts. |
| **3. API keys** | `GET /auth/api-keys`, `POST /auth/api-keys`, `DELETE /auth/api-keys/{id}` | **Stays — enabled for machine callers** | Authenticates non-interactive callers: the Jellyfin plugin's background webhook/health channel, Model Context Protocol (MCP) / LLM clients (`#564`), and scripts. |
| **4. OpenID Connect (OIDC)** | `snatcharr.oidc.enabled: false` (`GET /auth/sso`, `/auth/oidc/*`) | **Stays — optional, OFF by default** | Optional external IdP login (e.g. Authentik) for multi-service homelabs. Never required or assumed by any SnatchArr or Jellyfin plugin workflow. |
| **5. Trusted reverse-proxy SSO** | `snatcharr.proxy_auth.enabled: false` (`POST /auth/proxy-session`) | **Stays — optional, OFF by default** | Optional forward-auth header integration (`Remote-User`) from CIDR-trusted proxies. Never required or assumed. |

#### Revised bootstrap and linking semantics

1. **Jellyfin administrator bootstrap with a one-time setup code** (decided; [OQ-0035-4](#answered-questions) answer c, ledger `snatcharr-oq-0035-4`):
   - At first start with `CountUsers == 0`, SnatchArr prints a one-time setup code in its log. When `snatcharr.jellyfin.enabled = true`, the first Jellyfin user with `Policy.IsAdministrator == true` verified via `GET /Users/Me` on `POST /api/v1/auth/jellyfin` becomes the initial `admin` only after entering that code; SnatchArr then provisions the `users` row (`role = 'admin'`, `external_id = 'jellyfin:<id>'`, `password_hash = ''`) and records `(provider = 'jellyfin', subject = '<id>')` in `user_identities` in one transaction, and the code is spent. A wrong or reused code is refused, so a stranger holding some Jellyfin admin account cannot claim a fresh install, and the adopter still never invents a local password.
   - If the administrator later wants a break-glass local password for when Jellyfin is down, they set one from `/account` via `POST /api/v1/auth/password`.
2. **Jellyfin-first account linking without false `409 Conflict`** (decided; [OQ-0035-3](#answered-questions) answer a narrowed, ledger `snatcharr-oq-0035-3`):
   - When `snatcharr.oidc.enabled = false` and `snatcharr.proxy_auth.enabled = false` (the default), the `/account` page hides the external identity-linking card (`listIdentities`, `linkJellyfinIdentity`, `unlinkJellyfinIdentity`, `linkProxyIdentity`, `unlinkProxyIdentity`) because Jellyfin is the sole identity provider.
   - When an operator later enables OIDC or proxy SSO, the standalone `jellyfin:<id>` `users` row is merged into the signed-in row in one database transaction (reassigning user-owned foreign keys and attaching `user_identities(provider='jellyfin', subject=<id>)`) only when the signed-in user starts the link from the account page and proves the Jellyfin account live through `POST /api/v1/auth/identities/jellyfin`. The merge never runs automatically and never matches by username. `409 Conflict` stays for a `(provider, subject)` already linked to a *different* multi-identity account.
3. **Role resolution (`sso_role`)**:
   - For Jellyfin sessions (`sso_source = 'jellyfin'`), `sso_role` reflects Jellyfin's `Policy.IsAdministrator` (`admin` if true, else `default_role` — `requester` by default — unless downgraded to `viewer` by an explicit per-user role override or parental restriction).

### 4. UI placement: where every surface lives

1. **Inside Jellyfin for all users (`Plugin user page` + `Item detail button` + `Home section`)**:
   - Reachable from the **SnatchArr** link in Jellyfin's main navigation drawer (`MainDrawerContent.tsx`) and top toolbar (`UserViewNav.tsx`), opening `/SnatchArr/app`:
     - **Requests & Discovery**: Search and request missing movies, series, music, books, and adult scenes/image sets (`#565`, Seerr requests `listSeerrRequests`), and track personal and household request status.
     - **Watch-Aware Series Gate**: View series held by the season gate (`listWatchawareGateSeries`, `listWatchawareGateDecisions`) and trigger "Fetch Next Season Now" (`releaseWatchawareGateSeries`).

     - **Adult Favourites & Image-Set Galleries** (visible only when the `adult` module is enabled and the Jellyfin user's parental policy permits adult content): Follow favourite performers, studios, and tags across **stash-box** (`/ˈstæʃ.bɒks/`, the open-source GraphQL metadata server behind community metadata indexes, ADR-0027) and browse image-set galleries synced as Jellyfin `PhotoAlbum` items.
     - **Account Settings**: View session role, set a break-glass admin password, manage API keys (admin), or link secondary identities when OIDC/proxy SSO is enabled.
   - Contextual **Item detail buttons** on `#/details?id=<itemId>`: "Search Missing / Upgrade", "Fetch Next Season Now", download queue status/strike badge, "Follow Performer / Studio", and "View Linked Image Sets".
2. **Inside Jellyfin for administrators (`Dashboard config page`)**:
   - Reachable from **Dashboard -> Plugins -> SnatchArr** (`/#/configurationpage?name=SnatchArr`) and from the **Admin** switcher inside `/SnatchArr/app` when `role == 'admin'`:
     - Plugin bootstrap connection panel (`SnatchArrUrl`, one-click Jellyfin admin pairing, `Test Connection`).

3. **What stays only in the standalone SnatchArr UI and why**:
   - **Zero functional or administrative features are exclusive to the standalone UI.**
   - Only **three external/fallback authentication entrypoints** remain standalone-only (`/login` and `/setup` when accessed directly on SnatchArr's port) because they exist specifically for when Jellyfin is not the active host shell:
     1. Break-glass local password sign-in (`login`) and non-Jellyfin initial setup (`completeSetup`) when the Jellyfin container is down or not used.
     2. Standalone Jellyfin credential and Quick Connect sign-in prompts (`jellyfinQuickConnectInitiate`, `jellyfinQuickConnectAuthenticate`) — inside Jellyfin, the user is already authenticated to Jellyfin and the plugin exchanges their active session token silently.
     3. Optional OIDC redirect and reverse-proxy session bootstrap (`getSSO`, `createProxySession`) for multi-IdP homelabs.

## Consequences, risks, and alternatives considered

### Positive consequences

- **Complete single-app experience for any adopter**: Every SnatchArr user workflow and administrative setting is operable from inside Jellyfin with a single Jellyfin login, requiring zero Kubernetes, reverse proxy, TLS ingress, or external IdP setup.
- **Single frontend implementation (HISS-19)**: Serving `web/` in embedded mode through the plugin's `/SnatchArr/app` proxy avoids duplicating 18+ routes and 105+ API bindings in C# or vanilla JavaScript, preserving Paraglide (`en`/`de`) localization and `sveltesentio` WCAG 2.2 AA / EN 301 549 accessibility guarantees.
- **Zero-setup admin onboarding**: First-run Jellyfin administrator bootstrap removes the chicken-and-egg requirement of visiting standalone `/setup` before pairing the Jellyfin plugin.
- **Cryptographic session verification without static impersonation keys**: Token exchange against `GET /Users/Me` plus 5-minute revalidation ensures a leaked plugin config file cannot impersonate users or bypass parental controls.

### Risks and mitigations

- **`jellyfin-web` DOM and router evolution**: Upstream changes to `#/details` button containers (`src/apps/legacy/controllers/itemDetails/index.js`) or poster card markup in future Jellyfin releases can affect injected item buttons, poster buttons or the navigation entry.
  - *Mitigation*: All full-page workflows live inside `/SnatchArr/app` and `/web/ConfigurationPage?name=SnatchArr`; `SnatchArr/client.js` is restricted to small, defensive mount hooks tested in CI against the pinned `jellyfin/jellyfin:12.3` container.
- **Long-lived SSE connections through the C# plugin proxy**: Buffering by ASP.NET Core response middleware would stall real-time `snatcharr.v1.EventType` SSE updates (`GET /SnatchArr/api/v1/events`).
  - *Mitigation*: `SnatchArrProxyController` disables response buffering (`IHttpResponseBodyFeature.DisableBuffering()`), uses `HttpCompletionOption.ResponseHeadersRead`, and forwards `Last-Event-ID`.

### Alternatives considered

1. **Standalone SnatchArr UI only (status quo prior to this ADR)**:
   - *Rejected*: Forces every household member to learn a second URL and sign-in flow, requires adopters to expose a second port or configure a reverse proxy, and leaves item browsing disconnected from requesting, watch-aware season release, and adult galleries.
2. **Cross-origin `<iframe>` embedding pointing directly at SnatchArr's standalone port**:
   - *Rejected*: Requires the adopter to expose SnatchArr's HTTP/HTTPS port to every client browser, triggers third-party cookie blocking (`SameSite=Lax` / partitioned cookies) when Jellyfin and SnatchArr sit on different ports or hostnames, and fails under mixed-content rules when Jellyfin is served over HTTPS. Proxying `/SnatchArr/app` and `/SnatchArr/api` through the plugin controller keeps all traffic same-origin on the Jellyfin server port.
3. **Client-side script injection only (rebuilding all 18 routes as DOM-injected vanilla JS modals)**:
   - *Rejected*: Re-implementing 105 operations, complex policy forms, queue strike tables, and the adult matching audit queue in injected vanilla JavaScript would violate HISS-19, lose compile-time OpenAPI type safety (`web/src/lib/api/schema.d.ts`), and break across `jellyfin-web` Legacy vs Modern React transitions.

3. **Planted negative security cases (replayed red-then-green)**:
   - **Planted case 1 — Forged or expired Jellyfin token**: Presenting an invalid or expired token to `/SnatchArr/api/v1/auth/jellyfin` or `/SnatchArr/api/v1/instances` must return HTTP `401` with `Content-Type: application/problem+json`. Removing the `ByToken` check in `api/internal/jellyfin/authenticator.go` must cause the test to fail (red).
   - **Planted case 2 — Jellyfin server API key used on user-delegated plugin endpoint**: Calling `/SnatchArr/api/v1/*` through the plugin using a server-level Jellyfin API key (`User.GetIsApiKey() == true`) with a forged `X-Jellyfin-User-Id` header must be rejected with HTTP `403` / `401` and never mint an admin or user session.
   - **Planted case 3 — Role escalation (`requester` calling admin-only mutation)**: A non-admin Jellyfin user calling `PUT /SnatchArr/api/v1/settings` (`updateSettings`) or `POST /SnatchArr/api/v1/auth/api-keys` (`createAPIKey`) must receive HTTP `403 application/problem+json`.
   - **Planted case 4 — Disabled module and parental-control adult gate**: A Jellyfin user with `MaxParentalRating` set (or when the `adult` module is disabled) requesting `/SnatchArr/api/v1/adult/*` must receive HTTP `404 application/problem+json` with zero metadata leakage ([ADR-0025](0025-module-switches.md), [ADR-0028](0028-jellyfin-plugin.md)).
   - **Planted case 5 — Item search inside the cooldown**: a second item-scoped search by the same user inside the per-user cooldown must return HTTP `429 application/problem+json` and dispatch nothing; a search that would exceed the instance hourly cap is refused the same way (`snatcharr-oq-0035-2`). Boundary cases: a cooldown of 0 allows the second search at once, and a setting outside 0 to 3600 s is refused with HTTP `400` (`snatcharr-oq-0035-2-cooldown-cap-values`).
   - **Planted case 6 — Merge without live proof**: linking from the account page with a wrong Jellyfin password, or a matching username alone, must leave both user rows unchanged (`snatcharr-oq-0035-3`).
