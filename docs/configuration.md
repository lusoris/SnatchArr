# Configuration

The API reads its configuration from environment variables (prefix `APP_`), the worker
from `SNATCH_*`. Everything else is stored in Postgres and edited through the API or the
UI.

## Instances

Administrators register instances under `/instances` (`POST /api/v1/instances`). Supported `kind` values are the six \*arr kinds (`sonarr`, `radarr`, `lidarr`, `readarr` ([legacy](readarr.md)), `whisparr_v2`, `whisparr_v3`) plus `stash` ([ADR-0032](adr/0032-stash-own-or-integrate.md)). Instance API keys are write-only on the HTTP API and encrypted at rest with AES-GCM (`APP_CRYPTO_KEY`).

A `stash` instance is a companion only:

- **Companion only, never snatched**: `stash` instances never enter snatch planning (`ListInstancesToPlan`), worker leases, queue management, Seerr resolution, Configarr import, hourly stamina caps (`/api/v1/hourly-caps`), or priority presets.
- **Minimum version `v0.31.0`**: Connectivity probes (`POST /api/v1/instances/{id}/test` and `POST /api/v1/instances/test`) query the Stash GraphQL `version` field via `github.com/golusoris/goenvoy/mediaserver/stash/v2` and require Stash `0.31.0` or newer (for `.stashignore` support). Older versions are rejected with HTTP 422.

| `monitored_only` | true | |
| `skip_future_releases` | true | |

## Queue policy

Each instance has a queue policy (`GET/PUT /api/v1/instances/{id}/queue-policy`; `PUT` is
admin-only). When `enabled` is true, the elected replica sweeps the instance's *arr download
queue and counts consecutive strikes per download. `GET /api/v1/instances/{id}/queue-strikes`
lists the downloads that hold a strike now; downloads the last sweep found clean are left out.
The rules and their order are described in [ADR-0012](adr/0012-queue-management-replaces-cleanuparr-link.md).

Every rule starts in `observe` mode: a strike is recorded and shown, and the queue is left
alone. A rule in `act` mode removes the download once its strike count reaches the threshold;
every rule except `unwanted_unmonitored` also blocklists the release so the *arr searches again.
Whisparr v2 and v3 queues are swept and force-imported like the others: a v2 candidate needs
a mapped series and episodes, a v3 candidate a mapped movie.

### Rules

| Rule | Matches when | Default threshold |
| --- | --- | --- |
| `stalled` | Downloading, and the remaining size did not shrink since the last sweep (applies to torrents only) | 6 |
| `metadata_stuck` | A torrent still waiting for its magnet metadata; threshold in minutes since the item was added (30..1440) | 180 |
| `slow` | Downloading slower than `min_bytes_per_second` since the last sweep | 6 |
| `failed` | Queue status or tracked state is failed | 2 |
| `import_blocked` | The *arr cannot import the finished download | 6 |
| `unwanted_score` | Custom format score below `min_custom_format_score` | 1 |
| `unwanted_unmonitored` | The episode, movie, album or book is no longer monitored | 1 |

Queued, paused and delayed downloads, downloads being imported, and downloads younger than
the grace period are never evaluated.

### Policy fields

| Field | Default | Range | Meaning |
| --- | --- | --- | --- |
| `enabled` | `false` | bool | Sweep this instance's queue |
| `grace_seconds` | 900 | 0 to 86400 | Minimum age before any rule looks at a download (the UI edits it in minutes) |
| `min_bytes_per_second` | 0 | >= 0 | Floor for `slow`; 0 turns `slow` off |
| `min_custom_format_score` | unset | integer | Floor for `unwanted_score`; unset turns `unwanted_score` off |
| `max_removals_per_sweep` | 10 | 1 to 100 | Most downloads one sweep may remove |

## Runtime settings

`GET/PUT /api/v1/settings` (on `PUT`, an omitted `llm_enabled`, `brand_mark` or `sfw_mode` keeps the stored value):

| Field | Default | Meaning |
| --- | --- | --- |
| `history_retention_days` | 90 | 1 to 3650; how long events and finished runs are kept. The elected replica deletes older ones once an hour |
| `user_agent` | `SnatchArr/1.0 (...)` | Sent to every *arr and download client |
| `global_hourly_cap` | 0 | Stamina shared by every instance (0 = off) |

The same hourly pass also forgets afterglow entries 90 days after they expired, spent
stamina buckets after two hours, expired login sessions and workers that have not called
for `history_retention_days`. It deletes at most 100,000 rows
per table per pass and logs one `retention: purge pass` line with the counts. A larger
backlog shrinks over the following hours.

## Configarr

Point `APP_SNATCHARR_CONFIGARR_CONFIG` (and `_SECRETS`) at your Configarr files and every
`sonarr`, `radarr`, `lidarr`, `readarr` ([legacy](readarr.md)) and `whisparr` instance is
imported on start and kept in sync: the files are polled every 30 seconds (inotify misses Kubernetes ConfigMap
swaps, polling does not). Only `base_url`, `api_key` and the `enabled` flags are read;
`!secret`, `!env` and `!file` values are resolved like Configarr does. Whisparr entries are
probed to tell v2 from v3: the reported major version decides (2.x is Whisparr v2, 3.x is Whisparr v3). A probe
that fails keeps the kind already stored, with a warning; a Whisparr entry that was never imported, or one that
reports another major version, is not imported and the import result names why. An instance that disappears from the file is switched off, not
deleted. Imported instances are read-only in SnatchArr except for their snatch policy. Deleting
one that the file still declares, enabled or not, is refused with 403; once it is gone from the
file and switched off, it can be deleted.

`POST /api/v1/configarr/import` runs a one-shot import (with `config_path` and
`secrets_path` in the body, or the linked files); `GET /api/v1/configarr/status` shows
linked mode and the last result.

### Declarative Download Clients

When `APP_SNATCHARR_CONFIGARR_DOWNLOAD_CLIENTS` points to a YAML file, download clients are declaratively provisioned and kept in sync alongside instances:

```yaml
qbittorrent:            # section = domain.DownloadClientKind value; accept every kind ParseDownloadClientKind accepts
  main:                 # entry name -> key "qbittorrent/main", Name "main"
    base_url: http://qbittorrent.media.svc:8080
    username: !env QBIT_USER
    password: !file /etc/snatcharr/configarr-secrets/qbit-password
    instance: sonarr/main   # optional Configarr instance key; omitted = applies to every instance
    max_active: 0           # optional int
    max_queued: 0           # optional int
    bandwidth_budget_bps: 0 # optional int64
    enabled: true           # optional, default true
sabnzbd:
  main:
    base_url: http://sabnzbd.media.svc:8080
    api_key: !secret sabnzbd_api_key   # secret = api_key or password, exactly one, both -> parse error
```

`!secret` (resolved from `APP_SNATCHARR_CONFIGARR_SECRETS`), `!env` and `!file` tags work identically to instance secrets. When an entry disappears from the file, it is pruned. Provisioned clients are marked with source `configarr`; mutating or deleting them via the UI or API is rejected with 403 Forbidden.

### Declarative Policies

When `APP_SNATCHARR_CONFIGARR_POLICIES` points to a YAML file, snatch policies and queue policies are declaratively applied to Configarr instances:

```yaml
defaults:            # optional, applied to every Configarr instance first
  queue:
    enabled: true
instances:
  sonarr/series:     # Configarr key <app>/<name>, as Definition.Key
    snatch:
      missing_per_cycle: 2
      hourly_cap: 30
    queue:
      enabled: true
      rules:
        failed: { mode: observe, threshold: 2 }
```

Field names match the API JSON field names of `SnatchPolicy` and `QueuePolicy` in the OpenAPI specification. Policies are partial: only listed fields change, while unlisted fields keep their current stored value (merging instance entries over defaults, over stored values). The UI keeps editing policies; a later import overwrites the fields the file lists ("the file wins for the fields it names").

`!secret` (resolved from `APP_SNATCHARR_CONFIGARR_SECRETS`), `!env` and `!file` tags work identically to instance secrets. Declarative policies apply only to `source=configarr` instances; manual instances are untouched. Unknown instance keys, unknown fields, or values rejected by the service are reported as warnings in the import status while remaining instances apply.
